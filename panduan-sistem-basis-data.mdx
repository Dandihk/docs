## 1. Dasar Administrasi Basis Data

### Pengertian Basis Data & DBMS

**Basis Data (Database)** adalah koleksi data yang terorganisir dalam format tertentu dan disimpan secara elektronik. Tujuan utamanya adalah agar proses penyimpanan, pengambilan, dan manipulasi data dapat dilakukan dengan lebih efisien.

**Database Management System (DBMS)** adalah sistem perangkat lunak yang digunakan untuk menyimpan, mengatur, dan memastikan data tersimpan secara aman. Melalui DBMS, pengguna dapat menjalankan operasi CRUD (Create, Read, Update, Delete).

### Arsitektur & Database Server

- **Arsitektur Data:** Mendefinisikan teknologi dan struktur administrasi untuk mengelola sumber data organisasi agar pengguna dan pengembang dapat mengakses data secara fleksibel.
- **Database Server:** Basis data yang diletakkan pada jaringan komputer (lokal/interlokal) sehingga dapat diakses secara terpusat atau dibentuk menjadi _database cluster_ untuk pemrosesan masif.

### Derajat Relasi

Menjelaskan jumlah entitas yang berpartisipasi dalam suatu relasi (_relationship_):

1. **Unary Degree (Derajat Satu):** Melibatkan 1 entitas.
   - _Contoh:_ `Mahasiswa` $$\rightarrow$$ _bicara_
2. **Binary Degree (Derajat Dua):** Melibatkan 2 entitas.
   - _Contoh:_ `Mahasiswa` $$\rightarrow$$ _pergi_ $$\rightarrow$$ `Perpustakaan`
3. **Ternary Degree (Derajat Tiga):** Melibatkan 3 entitas.
   - _Contoh:_ `Mahasiswa` + `Ruangan` + `Mata Kuliah` $$\rightarrow$$ _belajar_

### Kardinalitas ERD

<AccordionGroup>
  <Accordion title="One to One (1 : 1)">
    Satu entitas A terhubung dengan paling banyak satu entitas B.

    ![Image](/images/image-10.png "Image")

    - **Contoh:** 1 `Mahasiswa` $$\rightarrow$$ _kuliah di_ $$\rightarrow$$ 1 `Universitas`
  </Accordion>

  <Accordion title="One to Many (1 : N)">
    Satu entitas A dapat terhubung dengan banyak entitas B, tetapi entitas B hanya terhubung dengan satu entitas A.

    ![Image](/images/image-11.png "Image")

    - **Contoh:** 1 `Mahasiswa` $$\rightarrow$$ _punya_ $$\rightarrow$$ N `Hobi`
  </Accordion>

  <Accordion title="Many to Many (N : N)">
    Banyak entitas A dapat terhubung dengan banyak entitas B.

    ![Image](/images/image-12.png "Image")

    - **Contoh:** N `Mahasiswa` $$\rightarrow$$ _belajar_ $$\rightarrow$$ N `Mata Kuliah`
  </Accordion>
</AccordionGroup>

## 3. Konsep Model Relational

**Relasi (Relational Model)** adalah gambaran struktur basis data berbasis _record_ yang direpresentasikan dalam bentuk tabel.

![Image](/images/image-14.png "Image")

### Hirarki & Istilah Basis Data Relasional

```xml
Database
 └── File / Tabel (contoh: Tabel Mahasiswa, Tabel Dosen)
      └── Record / Baris (contoh: 19312009 | Yunus | Informatika)
           └── Atribut / Field / Kolom (contoh: NPM, Nama, Jurusan)
                └── Data Value (contoh: "Yunus")
```

---

### Macam-Macam Key pada Database

<Tabs>
  <Tab title="Primary Key (PK)">
    Atribut unik yang dipilih sebagai pembeda utama antar baris data.

    ![Image](/images/image-15.png "Image")

    > **Tips Perancangan:** Menggunakan atribut manual seperti `NPM` sebagai Primary Key berisiko menyebabkan redundansi data. Disarankan menggunakan atribut tambahan seperti `IDMhs` bernilai numerik dengan fitur **Auto Increment**.
  </Tab>
  <Tab title="Foreign Key (FK)">
    Atribut pada suatu tabel yang merujuk pada Primary Key tabel lain untuk membentuk hubungan/relasi antartabel.

    ![Image](/images/image-16.png "Image")

    - **Contoh:** Atribut `IDMhs` di dalam `Tabel Matkul` berfungsi sebagai Foreign Key yang menghubungkan ke `Tabel Mahasiswa`.
  </Tab>
  <Tab title="Candidate Key">
    Atribut atau kumpulan atribut yang berpotensi menjadi Primary Key karena bernilai unik.
  </Tab>
  <Tab title="Alternative Key">
    Candidate Key yang tidak terpilih menjadi Primary Key.
  </Tab>
</Tabs>

<Note>
  **Tahap Selanjutnya:** Materi berikutnya adalah **Teknik Normalisasi pada Basis Data** untuk mengoptimalkan struktur tabel dan menghilangkan redundansi data.
</Note>
